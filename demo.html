The Degenerate Input Test: Silent vs. Loud Failure
Raw SDK Behavior
✓ VALID (Silent Failure)
The model, forced by tool_choice to fill every field, invented "<UNKNOWN>" placeholder strings. Pydantic accepted them. Downstream systems get garbage-but-valid data with no indication the input was garbage.
BAML Behavior
✕ BamlValidationError (Loud Failure)
The model returned null for required fields (honest). BAML's runtime enforced the schema: company_name: string cannot be null. Exception raised with field-level detail. Caught, not swallowed.

Schema Iteration: Adding key_hires: list[str]

Raw Anthropic SDK

4 Surfaces
1. Pydantic Model
class PortcoUpdate(BaseModel): ... key_hires: list[str] = [] sentiment: Literal["positive", "neutral", "concerning"]
2. Tool Description String
_TOOL = { "name": "extract_portco_update", "description": ( "... For key_hires, list each named hire as '<Name> (<role/title>)' when available; return an empty list if no specific hires..." ), ... }
3. System Prompt String
_SYSTEM = ( "... For key_hires, include only people explicitly named as new hires or recent joiners; do not include existing team members or open roles." )
4. Module Docstring
""" raw_baseline.py — portfolio update extractor... # Schema iteration time (raw SDK): ~2 minutes # (added key_hires: list[str] — touched Pydantic model, # tool description, system prompt, and this docstring) """
No compile-time link between these 4 surfaces. Tool description, system prompt, and Pydantic model can silently diverge. Risk of drift is high.

BAML

1 Surface
extraction.baml
class PortcoUpdate { company_name string reporting_period string arr_usd float? customer_count int? mrr_growth_pct float? runway_months float? key_updates string[] risks_flagged string[] /// Named new hires and recent joiners only. /// Format: "Name (Role)". Empty list if none mentioned. key_hires string[] sentiment Sentiment }
Regenerate Command
$ baml-cli generate ✓ Generated baml_client/ in 0.8s
Single source of truth. {{ ctx.output_format }} auto-renders the schema into the prompt. /// docstrings become prompt content. No drift possible.

Bugs & Findings

Things You'd Only Find If You Actually Shipped It

Real issues discovered during benchmarking on Windows

🔇
on_tick Callback Silent
b.with_options(on_tick=fn).ExtractPortcoUpdate(...) — the callback never fires in sync mode. No error, no warning. Streaming callbacks only work in async.
# Expected: fn() called during generation # Actual: fn() never called, silent pass
🪟
Windows stderr Uncapturable
BAML's Rust runtime writes INFO logs (including real token counts and latency) via the Windows Console API (WriteConsole), not fd 2. os.dup2 redirection doesn't work.
# Attempted: os.dup2(pipe, 2) # Result: Logs still go to console # Fix: Use count_tokens API instead
👀
No --watch Flag
baml-cli generate has no --watch mode. Every .baml edit requires manually re-running the command. Easy to forget, causes confusing schema mismatches.
# Desired: baml-cli generate --watch # Current: Must run manually after each edit # Risk: Python types ≠ .baml schema
